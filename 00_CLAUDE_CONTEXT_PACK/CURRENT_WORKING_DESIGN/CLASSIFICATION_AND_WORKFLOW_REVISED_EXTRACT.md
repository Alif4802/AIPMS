DESCO AIPMS - 10-Domain AI Context Classification (Revised)
Official 25 Grade 1-11 ACR metrics remain unchanged; revisions strengthen context boundaries and role-aware reasoning.
Review adjustment: The domain layer is retained, but its purpose is tightened. It is only an AI context/routing structure. Role-specific examples (technical work, team-leading situations,
office/admin work, safety/emergency situations) shape scenario interpretation; they do not create new official metrics or move the 25 ACR criteria.

Part A - Revised Primary Performance Input & AI Metric Mapping
Feedback applied: Hybrid input removed; domain selection and the mapping path are now explicit.
Input policy: the primary inputter records the performance event and evidence. They do not give the event an annual 1-4 ACR mark. The system first establishes a primary domain, then
maps the event only to directly relevant official metrics.
1. INPUT MODE
Quick Input
Write what happened naturally. AI proposes the primary domain first; the officer confirms it before metric
mapping.
Guided Input
Select one of the 10 domains and, if useful, a common scenario family; then describe the actual event.
2. ESTABLISH THE PRIMARY AI DOMAIN
Primary Domain Checkpoint
Quick Input: AI suggests domain -> human confirms. Guided Input: selected domain is confirmed. This domain becomes the normal mapping
boundary.
3. AI CONTEXT RETRIEVAL AND METRIC MAPPING
Domain Context
Load only the confirmed domain definition and
boundaries.
Scenario Library
Retrieve matching scenario families +
exclusion/boundary examples.
Official Sub-Metrics
Evaluate only official ACR metrics inside the
confirmed domain.
Cross-Domain Check
If strong evidence points outside the domain, flag it
separately for approval.
Human Mapping Review
Officer accepts/removes/adds metric links. Any cross-domain link requires explicit confirmation.
Store One Evidence Event + Evidence Profile
Store event once with confirmed metric links, direction, relevance, evidence reference and context. No
event-level 1-4 score.

Part B - Revised Evidence -> Metric Assessment -> Initial Pen Picture
Adds an explicit evidence-profile layer so the path from an event to the annual 1-4 recommendation is clear.
Assessment policy: an event is evidence, not an annual score. Each mapped event carries structured evidence signals; at appraisal time, all eligible evidence for one official metric is
considered together before AI recommends an integer 1-4 mark.
1. ELIGIBLE EVIDENCE SOURCES
Supervisor / Reporting Inputs
Confirmed year-round performance events and observations.
Approved System Facts
Attendance, training, rewards/recognition, finalized
discipline/compliance and other permitted facts.
Valid Employee Self-Input
Factual achievements/work completed with evidence; no self-rating
or self-score.
2. EVENT-LEVEL EVIDENCE PROFILE - NOT A SCORE
For each confirmed mapping, preserve: relevance (Primary/Secondary) | direction (supporting/contrary) | source/evidence reference | outcome/impact | period/frequency context
3. BUILD 25 SEPARATE OFFICIAL METRIC EVIDENCE SETS
Metric 8 - Reliability
Only evidence directly relevant to dependability/follow-through.
Metric 14 - Professional Knowledge
Only evidence that demonstrates job/technical knowledge.
... all 25 official metrics
No parent-domain score; sibling metrics do not inherit evidence
automatically.
Retrieve Approved Context
Official metric definition + domain boundary +
relevant scenarios/anchors.
Reason Across the Period
Consider repetition, contrary evidence, sufficiency
and role context.
AI Recommends 1-4
Integer suggestion + rationale + cited evidence; or
INSUFFICIENT EVIDENCE.
Officer Review -> Pen Picture
Reporting Officer reviews 25 recommendations; AI
then drafts the initial pen picture.
